訓練、資料、輸入輸出、使用與評估#

五個實作問題，每題都把 VLA 和 WM（世界模型）並排對照：怎麼訓練、資料怎麼建、輸入輸出是什麼、實際怎麼用、怎麼評估。

最核心的差別

VLA 學的是「看到這個、聽到這句話，該做什麼動作」（策略 π(a | o, l)）；世界模型學的是「現在是這樣、做了這個動作，世界接下來會變怎樣」（動態 p(o′ | o, a)）。所以 VLA 要「好的示範」，世界模型要「多樣的後果，包含失敗」。後面五題的差異幾乎都由此而來。

Q1 怎麼訓練？#

重點

現代 VLA 幾乎都是「站在 VLM 肩膀上」的多階段模仿學習，關鍵技術選擇是動作怎麼表示（離散 token 還是連續的擴散／flow matching）。世界模型則是「預測下一刻」的自監督學習，關鍵選擇是在哪個空間預測（像素、離散 token 或抽象潛空間）。

VLA 的四個階段#

動作怎麼變成可訓練的目標（最關鍵的設計）

方法 做法 損失函數 代表
均勻分箱 token 每個動作維度切成 256 個區間，對應到詞表裡的 token，像生成文字一樣逐一輸出 交叉熵（next-token） RT-2、OpenVLA
壓縮 token 對動作序列做 DCT 頻域轉換再 BPE 壓縮，token 數少很多，高頻動作也學得好 交叉熵 FAST（π0-FAST）
Flow matching／擴散動作專家 VLM 產生特徵，另一個小網路從噪聲逐步去噪出整段連續動作 速度場回歸／去噪 MSE π0、GR00T N1、Diffusion Policy
連續回歸＋平行解碼 一次輸出整段動作，用 L1 損失直接回歸，推論快很多 L1 OpenVLA-OFT
混合（知識隔離） VLM 用 FAST token 訓練，動作專家用 flow matching，並阻斷動作專家的梯度回流到 VLM 交叉熵＋flow matching π0.5＋KI

另一個幾乎所有模型都用的技巧是 action chunking：一次預測未來 H 步（例如 50 步，約 1 秒）而不是一步，減少誤差累積、讓動作更平滑。這來自 ACT／ALOHA。

規模參考

  • OpenVLA（7B）：Open X-Embodiment 中約 97 萬條軌跡，64 張 A100 訓練約 14 天。
  • π0（3.3B）：約 1 萬小時、7 種機器人、68 個任務的自有資料＋OXE 開源資料。
  • π0.5：加入多環境家庭資料、網路資料、「子任務文字標註」的高層預測，讓模型能在沒見過的家裡做清潔（論文）。
  • RL 後訓練：Physical Intelligence 的 π*0.6（Recap） 結合示範、人類介入修正與自主經驗，以學到的價值函數做優勢加權訓練。

世界模型的三條訓練路線#

  • A. 潛空間動態模型（為 RL 而生）：編碼器把觀測壓成潛狀態 z，遞迴網路（RSSM）學 zt, at → zt+1，同時預測獎勵與是否結束。損失＝重建＋KL＋獎勵預測。策略完全在想像的軌跡裡訓練。代表：World Models、DreamerV3、TD-MPC2（不重建畫面）。
  • B. JEPA：在表徵空間預測：不生成像素，遮住影片的一部分，讓模型預測被遮部分的表徵。代表：V-JEPA 2：先在超過 100 萬小時網路影片上自監督預訓練，再只用約 62 小時 DROID 機器人資料訓練動作條件的 V-JEPA 2-AC。
  • C. 影片生成式：把世界模型當「可被動作控制的影片生成器」。擴散／flow（在連續潛空間去噪）或自回歸（VQ tokenizer 把影格變成離散 token，再 next-token 預測）。代表：Cosmos、GAIA-1、UniSim、DIAMOND、GameNGen。
  • 沒有動作標籤怎麼辦？潛在動作：網路影片沒有記錄「按了哪個鍵」。Genie 用潛在動作模型（LAM）從前後兩幀自己推斷出 8 種離散動作，從約 3 萬小時遊戲影片無監督學出可操控的世界。LAPA 把同樣想法用在 VLA 預訓練上。

典型的影片世界模型訓練流程

  1. Tokenizer 訓練：先訓練影片編碼器（連續 VAE 或離散 VQ），把影片壓縮 8–16 倍以上，讓後續模型算得動。
  2. 大規模預訓練：在數百萬小時、無動作標籤的影片上，學「給定過去影格（和文字），預測未來影格」，學到物理常識和物體運動。
  3. 動作條件後訓練：在帶動作的資料（機器人、駕駛、遊戲）上微調，把動作注入模型（加到時間步 embedding 或 cross-attention），學「動作 → 後果」。
  4. （選用）蒸餾加速：把多步去噪蒸餾成少步才能即時互動，例如 Genie 3 可 720p、24 fps 即時生成。

Q2 資料集怎麼構建？#

重點

機器人資料是整個領域最大的瓶頸，因為不像文字和圖片可以從網路爬。業界的解法是一座「資料金字塔」。世界模型的資料工程重點則在海量影片的清洗與標註，以及保留失敗案例。

VLA 資料從哪裡來#

來源 怎麼收 優缺點 例子
真機遙操作 人用主從手臂、VR 頭顯、SpaceMouse 遠端操控機器人，同步記錄相機、關節與指令 品質最高、動作空間精確；但貴、慢 ALOHA、DROID
手持採集器 人拿著裝了相機的夾爪在真實環境操作，不需要機器人在場 便宜、可大量部署；需處理與機器人的形態差 UMI

從原始錄影到可訓練資料#

  1. 對齊時間：多路相機與關節訊號時間戳同步，統一重採樣頻率。
  2. 清理：刪掉機器人靜止不動的片段、失敗或操作者失誤的軌跡（若是純模仿學習）。
  3. 統一動作空間：跨機器人時通常轉成末端執行器的相對位移，或保留各自關節空間但補零到固定維度。
  4. 正規化：按每個資料集的 1%–99% 分位數把動作縮放到 [-1, 1]，避免離群值主導。
  5. 語言標註：補寫或改寫任務指令；π0.5 等模型還會標註細粒度子任務（「拿起海綿」「擦桌面」），可以用 VLM 自動重新標註。
  6. 配比：決定各資料集的採樣權重。OpenVLA、Octo 都花了大量功夫調配 OXE 子集比例。

世界模型的資料怎麼建#

無動作的海量影片（學物理常識），以 Cosmos 的管線為例：收集約 2,000 萬小時原始影片 → 鏡頭切分 → 過濾低畫質、靜止、字幕過多、純動畫 → 用嵌入向量去重 → 用 VLM 為每段寫文字描述 → 按類別平衡配比，最終約上億個片段。

帶動作的互動資料（學因果）

  • 遊戲：讓 RL 智能體玩遊戲同時記錄動作與畫面（GameNGen 用這種方式蒐集 DOOM 資料）。
  • 駕駛：車隊日誌包含方向盤、油門、速度與多相機影像（GAIA-1 用了約 4,700 小時倫敦駕駛資料）。
  • 機器人：沿用 VLA 的軌跡資料，但要特別保留失敗與隨機探索，否則世界模型只會預測成功，拿來評估策略時會過度樂觀。
  • 無標註影片：用潛在動作模型或逆動力學模型自動補動作。

Q3 輸入輸出是什麼？#

重點

VLA 的輸出是直接給馬達的控制訊號；世界模型的輸出是對未來的預測，本身不會讓機器人動起來，需要搭配策略或規劃器。

VLA π(at:t+H | ot, l)#

  • 輸入
    • 影像：1–3 路 RGB，常見是 1 個第三人稱＋1–2 個腕部相機，縮放到 224×224 左右。
    • 語言指令：「把襪子摺好放進抽屜」。
    • 本體感知（proprioception）：關節角度、末端位姿、夾爪開合度。
    • （部分模型）歷史幾幀影像、深度圖、觸覺。
  • 輸出
    • 動作 chunk：形狀 [H, D]，例如 π0 是 50 步 × 最多 18 維。
    • D 依機器人而定：單臂常用 7 維（6 自由度位移＋夾爪），雙臂 14 維，人形可達 30 維以上。
    • 控制頻率：RT-2／OpenVLA 約 3–6 Hz，π0／GR00T 可達 50 Hz 以上。
    • （分層或雙系統模型）π0.5 會先輸出子任務文字，再輸出低層動作。
輸入：
  images = [cam_high, cam_left_wrist, cam_right_wrist]   # 各 224×224×3
  prompt = "fold the towel"
  state  = float32[14]        # 雙臂關節角
輸出：
  actions = float32[50, 14]   # 未來 50 步的關節目標（50 Hz 下 ≈ 1 秒）

WM p(ot+1:t+k | o≤t, at:t+k)#

  • 輸入：過去觀測（前幾幀影像，或已編碼的潛狀態）＋條件訊號（機器人動作向量、駕駛操控、遊戲按鍵、文字描述、相機軌跡或潛在動作代碼）。
  • 輸出：
模型 輸出
DreamerV3 下一個潛狀態＋獎勵＋是否結束
V-JEPA 2-AC 未來影格的表徵向量（非像素）
Cosmos、UniSim 未來數秒的影片影格
Genie 3 可即時互動的 720p 畫面串流

Q4 使用方法是什麼？#

重點

VLA 的標準用法是「下載開源預訓練權重 → 在自己的機器人上收少量示範 → 微調 → 閉環部署」。世界模型很少單獨使用，它是其他系統的工具：訓練場、規劃器、資料工廠或評估器。

VLA：微調與閉環部署#

  1. 微調到自己的機器人：收集 50–200 條目標任務的遙操作示範，轉成 LeRobot 或 RLDS 格式；定義新機器人的動作維度與正規化統計值；用 LoRA 或全參數微調。開源工具：openpi（π0／π0.5）、OpenVLA、LeRobot（含 SmolVLA、ACT、Diffusion Policy）、Isaac GR00T。
  2. 閉環部署：
while not done:
    obs = robot.get_observation()            # 讀相機與關節
    chunk = policy.infer(obs, instruction)   # 輸出 [H, D] 動作
    for a in chunk[:k]:                      # 只執行前 k 步（receding horizon）
        robot.apply(a)
        sleep(1 / control_hz)
  • 執行策略：每次只執行 chunk 的前一部分再重新推論；或用 temporal ensembling 把重疊的 chunk 加權平均；或用 real-time chunking 在執行當下非同步推論下一段，避免動作卡頓。
  • 推論架構：大模型通常跑在旁邊的 GPU 伺服器，機器人透過網路收動作（openpi 就是 client-server 架構）；邊緣部署則需量化與蒸餾。
  • 安全：關節限位、速度上限、人類隨時可按急停。

世界模型的五種用法#

用法 怎麼做 例子
想像中訓練 策略在世界模型產生的虛擬軌跡中做 RL，不必碰真實環境 DreamerV3
模型預測控制（MPC） 取樣多組候選動作，在世界模型中各自推演，挑最接近目標的一組執行，每步重新規劃 V-JEPA 2-AC、TD-MPC2
合成訓練資料 生成新場景、新物體、新動作的影片，補上動作標籤後拿去訓練 VLA DreamGen

Q5 怎麼評估效能？#

重點

VLA 的黃金標準永遠是真機成功率，但它昂貴、難重現、樣本少，因此出現模擬基準與分散式評估。世界模型有一個常見陷阱：畫面好看 ≠ 物理正確 ≠ 對決策有用，必須多層評估，最後一定要看下游任務。

VLA 評估#

真機評估怎麼做才可信

  • 成功率：每個任務重複 10–20 次以上，固定初始擺放的分布；常加上部分得分（抓到了但沒放好得 0.5 分）。
  • A/B 盲測：同一組初始條件下輪流測試不同模型，評分者不知道是哪個模型。
  • 泛化軸：分別量測在新背景／光照、新物體、新位置、新指令說法、新機器人下的成功率下降多少。
  • 其他指標：完成時間、推論延遲與控制頻率、人類介入次數、長時任務平均完成子任務數。
  • 統計提醒：20 次試驗、成功率 50% 時，95% 信賴區間約 ±22%。兩個模型差 10% 往往不具統計意義。

世界模型的四層評估#

層次 問的問題 常用指標或方法
1 視覺品質 生成的畫面像不像真的？ FVD、FID、PSNR／SSIM／LPIPS、VBench
2 物理與一致性 物體會不會憑空消失？碰撞、重力對不對？轉回頭場景還在不在？ Physics-IQ 等物理基準、3D 幾何一致性、物體恆存測試、長時漂移
3 動作可控性 給不同動作，結果真的跟著變嗎？ 同一起點餵入不同動作比較差異（Genie 用 ΔPSNR）、與真實動作後果的軌跡誤差
4 下游有用度 拿它做決策有沒有幫助？ 用它規劃的真機成功率、用它訓練的 RL 分數（Atari 100k、DMC）、用它評估策略時與真機排名的相關係數

第 4 層最重要也最難。一個 FVD 很低的模型可能因為「太樂觀」而讓每個策略看起來都會成功，拿來評估就失去鑑別力，這就是世界模型資料要包含失敗案例的原因。
